## 1. 以“可观察行为”反推 Notion Web 的系统组成

Notion Web 要满足的可观察能力（对应系统）：

1) **块编辑器（Block Editor）**

- 块树（block tree）、块转换、嵌套、拖拽、粘贴解析、撤销/重做
- 富文本（inline marks）、@提及、链接、评论锚点

2) **数据库（Database）**

- Schema（属性类型）、记录页（record as page）
- 多视图：Table / Board / Timeline / Calendar / Gallery / List
- 过滤/排序/分组、Relation/Rollup、公式

3) **实时协作（Realtime Collaboration）**

- 多人同时编辑、冲突合并、presence（在线/光标/选区）、断线重连

4) **权限与共享（Permissions & Sharing）**

- 页面树继承、数据库与记录页权限、分享链接、访客、团队空间（如有）

5) **搜索（Search）**

- 全文检索 + 结构化字段检索（部分属性）
- 关键：**权限裁剪**（只返回用户可访问内容）

6) **文件/媒体（Files & Media）**

- 上传、存储、预览/缩略图、CDN 分发、权限控制

7) **通知（Notifications）**

- @提及、评论回复、提醒、订阅更新（in-app + 邮件/推送可选）

8) **AI（Notion AI）**

- 写作/改写/总结
- AI 搜索/问答（RAG）
- 结构化提取（行动项、要点、字段填充等）

## 2. Web 前端技术栈（推断）：应用层、编辑器层、视图层

> 由于 Notion 并未完整公开实现细节，此处为高概率推断与常见工程形态总结。
> 

### 2.1 应用层（Web App Shell）

可能形态（推断）：

- **语言**：TypeScript（高概率），历史代码可能混用 JS
- **UI 框架**：React（高概率）
- **组件系统**：高度自研（菜单/弹层/选择器/表格/虚拟列表/图标体系）
- **路由/导航**：SPA 路由（React Router/自研）+ 深链接（页面、block、数据库视图）
- **状态管理（宏观）**：
    - 全局：用户、工作区、权限、侧边栏树、搜索结果、通知等
    - 局部：页面编辑状态、数据库视图状态、弹层状态
    - 可能采用 Redux/MobX/Zustand/自研 store 的组合（团队演进常见）

### 2.2 编辑器层（Block Editor）：数据模型与渲染

Notion 的核心是“块树 + 行内富文本”。

#### 2.2.1 数据模型（推断）

- **Block**：`id`、`type`、`properties`、`children[]`
- **Inline text**：文本片段 + marks（bold、link、color、code、mention）
- **页面**：块树的根容器 + 元信息（title、icon、cover、properties）

#### 2.2.2 操作模型：用“可序列化操作”驱动一切

为了实现撤销/重做、协作合并、同步与审计，常见设计是把用户操作抽象为 operations，例如（示意）：

- `insert_text`, `delete_text`
- `insert_block`, `delete_block`
- `move_block`, `indent_block`, `outdent_block`
- `set_block_type`, `set_block_props`
- `set_page_props`

这些 operations 通常具备：

- 可重放（replay）
- 可合并（merge/compact）
- 可在网络上传输（协作广播）

#### 2.2.3 光标与选择（Selection）

- 选择定位常用：`(blockId, offset)` 或 `(path, offset)`
- 对中文输入法（IME）需要专门处理 composition 事件，避免光标错乱、重复插入

#### 2.2.4 渲染与性能（Performance）

Notion Web 的性能瓶颈主要来自：

- 大页面：块数量多、嵌套深、图片/数据库视图混合
- 高交互密度：hover affordance、拖拽、弹层

常用手段（推断）：

- 虚拟化（对长列表/数据库表格行）
- 分段加载（按需拉取块、折叠块懒加载）
- 局部更新（memoization、避免整树重渲染）
- 输入优化（批量更新、requestIdleCallback、节流/防抖）

### 2.3 数据库视图层：表格/看板/时间线等的前端实现

#### 2.3.1 Table（表格）

关键能力与实现点（推断）：

- 行/列虚拟化（windowing）
- 列宽拖拽（resize）
- 单元格编辑器按属性类型切换（select/date/person/relation/files…）
- 复制粘贴（跨多格）与粘贴解析（CSV/TSV）
- 排序/过滤在视图状态中表达（并同步到 URL 或服务端）

#### 2.3.2 Board（看板）

- 列 = 分组字段的枚举值（Status/Select）
- 拖拽卡片跨列 = 更新该字段
- 列汇总（count / sum 等）通常前端展示，数据来源可能由后端聚合提供

#### 2.3.3 Timeline / Calendar（时间线/日历）

- 核心是“时间区间布局算法”：避免重叠、支持缩放粒度
- 拖拽移动/拉伸 = 更新日期字段（start/end）
- 大量事件时需要虚拟化与局部重排

## 3. Web 后端技术栈（推断）：API、存储、协作、搜索、权限

### 3.1 API 形态：GraphQL / REST（可能混合）+ 协作通道

Notion Web 的请求形态通常会呈现：

- “页面打开”需要一次性取回：页面元信息 + 一段块树 + 权限 + 侧边栏相关
- “增量编辑”需要：高频、小 payload、低延迟

因此常见组合（推断）：

- **业务 API**：GraphQL 或 REST（甚至混合）
- **实时协作通道**：WebSocket（高概率）用于操作广播、presence、重连同步

### 3.2 主数据存储：结构化 + 文档化混合（Polyglot）

Notion 的数据天然是混合型：

- 结构化：workspace/user/permission、数据库 schema、属性定义
- 文档化：块树、富文本、页面内容

常见落地（推断）：

- 关系型数据库（PostgreSQL/MySQL）存结构化主数据
- 页面/块内容可能：
    - 存在关系型的 JSONB 字段里，或
    - 用文档型存储（MongoDB 等），或
    - 自研内容存储层（大型产品常见）
- **缓存**：Redis（会话、权限结果、热点页面、协作 session）
- **对象存储**：S3 类（文件、图片、导出产物）+ CDN

### 3.3 实时协作：OT / CRDT + Operation Log

#### 3.3.1 目标

- 多人编辑时“尽量不冲突”，用户感知为实时合并
- 断线/多端重连后仍能恢复一致状态

#### 3.3.2 两条主流路线（推断）

- OT（Operational Transform）
- CRDT（更利于离线/多端与最终一致）

Notion 的复杂点在于：

- 不只是长文本，还包括 block tree 的结构操作（move/indent/turn into）

工程上常见做法（推断）：

- 文本层（inline）用 OT/CRDT
- 结构层（block tree）用可序列化的结构操作日志（structural ops）
- 服务端负责：
    - 协作 session 管理
    - 广播 ops
    - 持久化与快照（snapshot）
    - 重连时的增量补齐（catch-up）

Presence：

- 通常是轻量、短 TTL、存内存/Redis 的状态流

### 3.4 权限系统：继承、共享链接与裁剪

Notion 权限的关键难点是“树 + 多入口 + 搜索裁剪”。

推断的实现要点：

- 权限继承：父页面/数据库对下游内容生效
- 共享链接：通过 token 代表访问主体或临时授权
- 性能：权限计算需要缓存与失效策略（例如当分享设置变更时批量失效）
- 与搜索耦合：搜索必须：
    - 索引时写 ACL（或 workspace scope + entity scope），并在查询时过滤；或
    - 查询后再做权限裁剪（但会浪费检索与排序）

### 3.5 搜索系统：倒排 +（可选）向量 + 权限

推断常见组件：

- Elasticsearch / OpenSearch 或自研倒排索引

索引对象：

- 页面标题、正文文本（块内容抽取）
- 数据库：部分属性字段（text/select/status 等）
- 关系/汇总/公式多半不直接索引或以可显示结果索引（取决于实现）

权限策略（关键）：

- 文档级 ACL 字段
- 查询时 filter + rerank（或 post-filter）

## 4. Web 场景的 AI 技术栈（推断）：Notion AI 如何“接入产品”

### 4.1 AI 功能分层

1) **生成类（Writing）**：改写、续写、总结、提炼要点

2) **问答类（Q&A）**：对工作区内容提问（RAG）

3) **抽取与结构化（Extraction）**：行动项、决策、字段填充、分类打标

4) **批处理/自动化（Batch/Automation）**：对数据库批量生成摘要/标签

### 4.2 模型层：LLM Gateway（模型网关）

推断 Notion 会用一个统一网关来：

- 统一鉴权与限流（保护成本与稳定性）
- 模型路由（不同任务用不同模型：质量/成本/延迟权衡）
- 安全策略（敏感信息、合规控制）
- 观测与审计（日志、token 成本、失败率）

### 4.3 RAG（检索增强生成）详解：Web 端的“AI 搜索/问答”

典型流水线（推断）：

1) 用户问题（Web）→ query 规范化/改写（可选）

2) 检索（Hybrid）：

- 倒排检索（关键词）
- 向量检索（embedding）

3) **权限裁剪**：严格只用用户可访问内容

4) 片段重排（reranker）

5) 上下文组装（chunk 拼接、去重、长度控制）

6) LLM 生成答案

7) 引用（citations）：把答案映射回“页面/块”以便可点击溯源

向量索引组件（推断）：

- Embedding 模型（第三方或自研）
- 向量存储：
    - OpenSearch/Elastic 的向量能力，或
    - 专用向量数据库（Milvus/Weaviate/Pinecone 等）

### 4.4 AI 与编辑器的结合（Web）

Web 端常见交互：

- 读取“当前选区/当前块/当前页面上下文”
- 注入提示词模板（prompt template）
- 输出以块形式插入或替换（避免破坏块树结构）

工程要点（推断）：

- 输出必须结构化：文本分段、标题、列表要映射到块类型
- 防止 prompt injection：当上下文来自用户内容时要隔离与清洗
- 限流与重试：前端提供 loading / cancel；后端可中断生成

### 4.5 AI 批处理：数据库列填充/摘要/分类

当用户对数据库“批量处理”时，系统需要：

- 队列（job queue）+ worker
- 并发控制（速率限制）
- 失败重试与幂等（idempotency key）
- 结果回写（写入属性字段）+ 可见的进度反馈

### 4.6 安全与隐私（AI 视角）

推断必备策略：

- Workspace 隔离：embedding/向量索引按 workspace 或更细粒度隔离
- 日志脱敏：prompt 与上下文不可直接长久保存或需要脱敏
- 管理开关（企业）：是否允许把数据发送给第三方模型供应商

### 4.7 LLMOps：质量评测与在线监控

常见体系（推断）：

- 离线评测集：问答正确率、引用命中率、幻觉率
- 在线 A/B：不同检索策略/不同模型/不同提示词
- 监控：延迟、成本、失败率、用户反馈

## 5. 复刻 Notion Web（仅 Web）的参考技术选型清单（工程参考）

> 这是“如果你要做一个 Notion-like Web 产品”，相对可落地的一套组合。
> 

### 5.1 Web 客户端

- React + TypeScript
- 编辑器：ProseMirror/Tiptap（inline 文本）+ 自研块层（block tree）
- 协作：Yjs（CRDT）或自研 OT
- 数据库表格：虚拟列表 + 单元格编辑器体系 + 快捷键与复制粘贴
- 构建与发布：Vite/webpack + code splitting + CDN

### 5.2 服务端

- API：GraphQL（Apollo）或 REST（Fastify/NestJS/Go）
- 协作：WebSocket + CRDT/OT 服务
- 存储：PostgreSQL（JSONB）+ Redis
- 搜索：OpenSearch/Elasticsearch（倒排）+（可选）向量检索
- 队列：Kafka/RabbitMQ + worker
- 文件：S3 + CDN + 预览服务（thumbnail/PDF）

### 5.3 AI

- LLM 网关：统一路由/限流/日志/策略
- RAG：Hybrid search + reranker + 引用生成
- 向量：OpenSearch kNN / Milvus
- 评测：离线 eval harness + 在线指标面板

## 6. 如果你要我继续“更细”：下一步可扩写到哪些层级

你说“越细越好”，接下来通常会扩写到“架构设计文档级别”，例如：

- Web 编辑器：
    - block schema（每种 block 的字段定义）
    - operations 定义表（操作类型、参数、前置条件、可逆性）
    - selection 模型、IME 处理策略
    - 性能策略（虚拟化、分段加载、渲染切片）
- 协作：
    - 协作消息协议（join/ack/op/presence/snapshot）
    - 快照与增量同步
    - 幂等与重放
- 搜索：
    - 索引 schema（字段、分词、更新策略）
    - 权限裁剪（ACL 字段设计与缓存）
- AI：
    - chunk 策略、embedding 更新策略
    - hybrid 检索与 rerank
    - 引用生成算法（答案片段 → block 映射）
    - prompt injection 防护与敏感信息检测
